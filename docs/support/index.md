# ทีม Support — วิธีการทำงาน

หน้านี้บันทึกวิธีการทำงานจริงของทีม **Support** ของ PGW Provider — ต่างจากหน้าอื่นในเอกสารชุดนี้ตรงที่**ไม่ได้มาจากการสำรวจหน้าจอ UI ทีละเมนู** แต่มาจากการอธิบาย workflow จริงพร้อมตัวอย่างเคสจริงจากทีมงาน

!!! danger "หมายเหตุความแม่นยำของเอกสารส่วนนี้"
    เนื้อหาหน้านี้มาจากตัวอย่างเคสจริงที่ทยอยสะสมมา (unknown_deposit/unmatch, ลูกค้าผูกหลาย merchant, Withdraw ค้าง Created, Unmatched backlog) — ยังไม่ครอบคลุมทุกเคสประเภทที่ทีม Support เจอในแต่ละวัน โดยเฉพาะฝั่ง **Withdraw/Topup/Settlement** ที่มีหลักฐานน้อยกว่าฝั่ง Deposit มาก — ต้องรอตัวอย่างเพิ่มเติมก่อนจะสรุปภาพรวมได้ครบ ดูคำถามค้างทั้งหมดที่ [คำถามที่ยังไม่มีคำตอบ](../open-questions.md)

## ภาพรวม — ศูนย์กลางการทำงานอยู่ที่ Telegram

ทีม Support ใช้ **Telegram** เป็นช่องทางหลักในการรับแจ้งปัญหาจากร้านค้า (Merchant) และประสานงานภายในทีม โดยมีบอทชื่อ **"JoinPay Support Bot"** ทำหน้าที่เชื่อมสองฝั่งเข้าด้วยกัน

## โครงสร้างห้อง Telegram (เท่าที่เห็น)

| ห้อง | รูปแบบชื่อ | หน้าที่ |
|---|---|---|
| ห้อง Support ต่อร้านค้า | `[JoinPay][Support] {รหัสร้านค้า}` เช่น `[JoinPay][Support] UOK168` | ห้องที่ End User/พนักงานร้านค้าส่งปัญหา (เช่น สลิปโอนเงิน) เข้ามาโดยตรง — มี JoinPay Support Bot เป็น admin ประจำห้อง |
| ห้อง Ticket กลาง | `[Ticket] JoinPay` | ห้องรวมศูนย์ที่บอท forward ทุกเคสจากห้อง Support ย่อยทุกร้านเข้ามา พร้อมสร้างเป็น ticket แบบ structured ให้เจ้าหน้าที่ไล่ดูทีเดียว |

!!! question "คำถามค้าง"
    รูปแบบชื่อห้อง `[JoinPay][Support] {รหัสร้านค้า}` — ชื่อ "JoinPay" ในชื่อห้องคงที่เสมอ หรือเปลี่ยนตามพาร์ทเนอร์ (เช่น `[NextPay][Support] ...` สำหรับร้านค้าฝั่ง NextPay)? ยังไม่เคยเห็นตัวอย่างของพาร์ทเนอร์อื่น

## บอท "JoinPay Support Bot" และคำสั่ง `/md`

เมื่อลูกค้าฝากเงินแล้วระบบ**จับคู่อัตโนมัติไม่ได้** (กลายเป็น `unknown_deposit` — ดู [Admin Console → Transactions](../console/payment/transactions.md)) ผู้ที่พบปัญหาจะพิมพ์คำสั่ง:

```
/md {pre-transaction UUID}
```

พร้อมแนบรูปสลิปโอนเงินเป็นหลักฐาน ในห้อง Support ของร้านค้านั้นๆ

!!! tip "กลไกของคำสั่ง /md"
    คำสั่งนี้ทำให้ JoinPay Support Bot **forward ข้อความ + รูปสลิปเข้าไปที่ห้อง `[Ticket] JoinPay`** โดยอัตโนมัติ พร้อมสร้างสรุป ticket แบบ structured:

    ```
    หัวข้อ: unmatch
    กลุ่ม: [JoinPay][Support] UOK168
    เจ้าหน้าที่ร้านค้า: null
    ข้อความ: /md {UUID}
    --------------------
    เคส: unknown_deposit
    สถานะ: open
    ทางเข้ากลุ่ม: https://t.me/+...
    ```

    เมื่อเจ้าหน้าที่ดำเนินการเสร็จ ticket จะถูกอัปเดตเพิ่มบรรทัด:

    ```
    🔍 ตรวจสอบ โดย: @{Telegram handle เจ้าหน้าที่}
    --------------------
    ✅ อนุมัติ โดย: @{Telegram handle เจ้าหน้าที่}
    ```

!!! question "คำถามค้าง"
    - `/md` เป็นคำสั่งเดียวที่ใช้ หรือมีคำสั่งอื่นสำหรับเคสประเภทอื่น (เช่นเคสที่ไม่ใช่ unknown_deposit)?
    - field "เจ้าหน้าที่ร้านค้า: null" ในตัวอย่างที่เห็นเป็นค่าว่างเสมอ หรือบางครั้งมีค่า — ใช้ระบุอะไร?

ดูตัวอย่างการใช้คำสั่งนี้ในเคสจริงที่ [เคสที่พบบ่อย](common-cases.md)

## บุคคล/role ที่เจอในตัวอย่าง

พบ Telegram handle รูปแบบ `@[PM][TS]-{ชื่อ}-` เช่น `@[PM][TS]-Lady Sherry-` ใช้เป็นทั้งผู้ตรวจสอบ (🔍) และผู้อนุมัติ (✅) ในเคสเดียวกัน

!!! question "คำถามค้าง"
    `[PM]` และ `[TS]` ย่อมาจากอะไร (เช่น Project Manager, Technical Support)? เป็น role tag ที่ติดหน้าชื่อ Telegram ของพนักงานทุกคนในทีม หรือเฉพาะบางคน? มี role อื่นอีกไหมนอกจาก PM/TS?
