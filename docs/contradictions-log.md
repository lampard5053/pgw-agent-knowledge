# Contradictions Log — จุดที่ข้อมูลขัดแย้งกันเอง (สะสมต่อเนื่อง)

> ไฟล์นี้ต่างจาก `open-questions.md` (ที่เก็บ "สิ่งที่ยังไม่รู้") และ `case-log.md` (ที่เก็บ "เคสจริงจากบทสนทนา") — ไฟล์นี้เก็บเฉพาะ **จุดที่ข้อมูล 2 แหล่งขึ้นไปในสกิลนี้ (หรือข้อมูลใหม่ที่เพิ่งได้รับ vs ข้อมูลเดิมที่มีอยู่แล้ว) พูดไม่ตรงกัน** ไม่ว่าจะเป็นระหว่างไฟล์ reference สองไฟล์, ระหว่างเอกสารกับสิ่งที่เห็นจริงในภาพหน้าจอ, หรือระหว่างสิ่งที่ผู้ใช้เพิ่งบอกกับสิ่งที่บันทึกไว้ก่อนหน้า
>
> **หลักการ:** ห้ามเลือกเชื่อฝั่งใดฝั่งหนึ่งเงียบๆ แล้วเขียนทับของเดิม — ต้องบันทึกทั้งสองฝั่งไว้คู่กัน พร้อมระดับความมั่นใจ แล้วค่อยตัดสินใจว่าจะถามผู้ใช้ตอนนั้นเลย หรือเก็บเป็นความสงสัยไว้ก่อน (ดูเกณฑ์ด้านล่าง)

## เกณฑ์ตัดสินใจ: ถามทันที vs เก็บความสงสัยไว้ก่อน

**ถามผู้ใช้ทันทีในบทสนทนา เมื่อ:**
- ความขัดแย้งกระทบการตัดสินใจที่กำลังจะเกิดขึ้นตอนนี้ (เช่น จะบอกยอดเงิน/สถานะ/ค่า config ให้ผู้ใช้ทำตาม แต่สองแหล่งบอกไม่ตรงกัน)
- เป็นเรื่องเงิน/ความเสี่ยงสูง (fee, balance, manual credit, ban/freeze) — ผิดพลาดแล้วแก้ยาก
- ผู้ใช้เพิ่งให้ข้อมูลที่ตรงข้ามกับสิ่งที่ระบบเคย "ยืนยันแล้ว" ไว้ในไฟล์อื่น — ต้องเช็คให้ชัดว่าของเก่าเคยผิด หรือของใหม่เป็นกรณีพิเศษ

**เก็บไว้เป็นความสงสัยก่อน (บันทึกในไฟล์นี้ + ตอบคำถามหลักไปตามปกติ โดยระบุ caveat สั้นๆ) เมื่อ:**
- เป็นรายละเอียดปลีกย่อยที่ไม่กระทบคำตอบตอนนี้โดยตรง
- ยังไม่มีหลักฐานเพียงพอจะฟันธงว่าใครถูก/ผิด (เช่น เห็นแค่ครั้งเดียว ยังไม่ confirm ซ้ำ)
- ถามไปก็ทำให้บทสนทนาสะดุดโดยไม่จำเป็น เพราะผู้ใช้ถามเรื่องอื่นอยู่

## Template

```
## [YYYY-MM-DD] หัวข้อความขัดแย้งสั้นๆ

**แหล่งที่ 1:** ระบุไฟล์/บทสนทนา + เนื้อหาที่บอก
**แหล่งที่ 2:** ระบุไฟล์/บทสนทนา + เนื้อหาที่บอก (ที่ขัดกับแหล่งที่ 1)
**ทำไมถึงขัดแย้งกัน (ถ้าพอเดาได้):** เช่น คนละเวอร์ชันของระบบ, คนละแบรนด์, ข้อมูลเก่าล้าสมัย, เข้าใจผิดตอนสำรวจ
**การจัดการ:** ถามผู้ใช้แล้ว → คำตอบคือ... / ยังไม่ถาม เก็บเป็นความสงสัยไว้ก่อนเพราะ...
**สถานะ:** ยังขัดแย้งอยู่ (unresolved) / คลี่คลายแล้ว (resolved — เขียนว่าใครถูกและอัปเดตไฟล์ต้นทางแล้วหรือยัง)
```

*(ยังไม่มีเคสขัดแย้งที่บันทึกไว้ — เพิ่มรายการแรกเมื่อเจอ)*
